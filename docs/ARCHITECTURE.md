# 技术架构与阶段边界

## 当前实现：Phase 1

Phase 1 使用 Node.js 原生 HTTP 服务提供本地 Web 应用，不引入外部运行时依赖。

```text
server.mjs                 本地静态文件服务
public/index.html          页面入口
public/styles.css          UI 设计系统与响应式布局
public/app.js              导航、页面渲染、本地任务数据
浏览器 localStorage        Phase 1 本地任务持久化
```

当前真实可用的功能：

- 首页和五个一级导航入口；
- 新建采集任务基础表单；
- 任务保存到当前浏览器的 `localStorage`；
- 首页最近任务列表读取已保存任务；
- 明确标识尚未实现的真实采集能力。

当前明确未实现：

- 社交平台登录状态读取；
- 作品页面访问、截图和互动数据解析；
- Excel/CSV 批量导入；
- Word 导出与历史 Word 更新。

## 后续模块边界

后续实现按职责拆分，避免将平台逻辑集中到单一文件：

```text
采集任务 UI
  └─ 任务编排器 / 持久化
       ├─ 平台适配器（TikTok / Instagram / Facebook / 抖音 / 快手）
       ├─ 页面访问与截图服务
       ├─ 数据解析与字段状态
       ├─ 结果审核与重试
       └─ Word 导出 / 字段级更新 / 对比报告
```

Phase 2 只接入单条作品链接闭环：打开页面、截图、读取可见数据、展示结果、保存截图。不会在 Phase 1 提前实现这些能力。

## 本地运行

```powershell
npm run dev
```

然后打开 `http://127.0.0.1:4173`。
